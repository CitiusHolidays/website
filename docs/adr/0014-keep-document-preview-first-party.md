# Keep document preview processing first-party

Staff Workspace document previews are rendered by the Citius application rather than by sending file bytes or public file URLs to an external document-viewer service. This preserves the existing Commercial File and Sensitive Travel Document access boundaries at the cost of operating the viewer and any Office-artifact preparation ourselves.

## Consequences

- Preview requests reauthorize the source file and never expose a browser-visible storage URL.
- Supported previews are enabled by default now that the first-party viewer is released. `DOCUMENT_PREVIEW_ROLLOUT_STAGE` and the corresponding public frontend stage remain synchronized rollback controls: `off` is the emergency kill switch, narrower stages step back through native Commercial Files, Commercial Office files, the Commercial Record Chain, and sensitive files, and invalid values fail closed.
- Preview artifacts retain the source file's authorization, retention, and deletion lifecycle rather than becoming independently shareable documents.
- Word and PowerPoint render as inert pages in an isolated browser worker and may use a compatible private paged artifact when one is available. Spreadsheet previews recalculate an initial safe formula subset covering `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `COUNTA`, basic arithmetic, ranges, and references within the same workbook. Unsupported formulas may show their stored workbook result only when clearly marked as not recalculated; macros, user-defined or volatile functions, scripts, external links, and external workbook data never execute.
- Native and browser-renderable Office previews open immediately. Additive Office preparation metadata is scheduled after upload and created lazily for existing files; a separately operated artifact worker can claim that work without delaying the source workflow. Preview artifacts have no independent retention lifecycle: replacement invalidates them, source deletion hides them, restoration restores or regenerates them, and permanent purge removes them.
- Office preparation starts immediately after upload without delaying upload completion, and lifecycle-coupled preview artifacts are cached aggressively. Before release, a representative corpus across every supported format and sizes through 15 MB establishes the fastest stable p50 and p95 budgets compatible with isolation and Staff Workspace responsiveness; those measured budgets become regression gates rather than granting uncached conversion an arbitrary fixed allowance.
- Preview processing treats every document as hostile input: browser workers load only same-origin application/WASM assets, external document content and links stay disabled, and resource/time limits fail closed for Preview when safety cannot be established. Any separately activated artifact converter must preserve the same no-external-content boundary.
- Extracted text remains scoped to search inside the currently open document. It is not added to a CRM-wide index or retained in logs; telemetry is limited to privacy-safe format, size band, document dimensions, duration, outcome, and sanitized error categories.
- An unrenderable file remains downloadable by an already-authorized user and is reported as a preview failure rather than sent to a fallback third-party viewer.
- Legacy binary `.doc`, `.ppt`, and `.xls` inputs remain downloadable but unavailable in Preview until a bounded isolated renderer/converter can preserve their document structure. They are never parsed on the Staff Workspace main thread.
